How it works

A reflex for the page.
An agent for the follow-up.

Two always-on processes inside your cluster. Neither holds a tool that can change anything.

Alertmanager → ingest-api
Webhook validated and queued on a Redis Stream. Nothing else is parsed here.
collectors
Kubernetes events, pod logs, Prometheus, Loki, CloudWatch. Fixed set, small caps, bounded windows.
redaction
Secrets, tokens, cloud keys, e-mails, IPs masked before any model sees anything. No off switch.
dedup · storm · correlation
Thirty pods with one alert: one call. Three alerts in one namespace: one revised hypothesis.
one model call
Hard timeout, daily budget, the context stored as an audit trail of exactly what the model saw.
Slack · Telegram · MCP
The message above. Then ask follow-ups in the chat, or from your own agent.

A pipeline, not an agent loop

One bounded call per alert, predictable cost: about $0.001 on a cheap cloud model, $0 locally.

It recommends. It never acts.

Read-only credentials, no write tools, output is text and never executed. An on-call bot that can act turns every false positive into an incident.

Which model is a setting

Local Ollama, Mistral, DeepSeek, Gemini, anything OpenAI-compatible; local-first with a cloud fallback. The code never changes.

Fastest way to see it

Install, and it pages itself.

With the demo switch on, a Job breaks one pod in the release namespace (under its own service account; the product's stays read-only) and the first real hypothesis lands in your chat minutes after the images are pulled.

kubectl create namespace minus20
kubectl -n minus20 create secret generic m20-telegram --from-literal=bot-token='<token>'
helm install m20 oci://ghcr.io/maxuver/charts/minus20 -n minus20 \
  --set config.notifier=telegram --set config.telegramChatId=<your chat id> \
  --set config.llmProvider=ollama --set config.ollamaUrl=http://<ollama>:11434 \
  --set demo.chaos.enabled=true

No Ollama? Any OpenAI-compatible key: --set config.llmProvider=openai --set config.openaiBaseUrl=https://api.mistral.ai/v1. Images are multi-arch, signed with SLSA provenance (gh attestation verify), scanned by Trivy and shipped with an SBOM. Already running it? Paste kubectl describe pod into the bot and get the same message without an alert.
